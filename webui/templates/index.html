How the checks work

The model never states a number

It picks the eight CVSS metrics — judgement calls. The score is then computed in code from CVSS v3.1 arithmetic. A model never asked for a number cannot invent one, and the output schema rejects a score field outright if it tries.

Two sources of truth, nothing else

Every claim must trace to the scanner output or a local CWE catalogue. CVE citations, CWE identifiers, URLs, scores and impact language are each checked against them.

Verified in code, not by the model

Asking a model to check its own work does not help: the process that invented the CVE will happily confirm it is real. Verification happens against data the model cannot influence.

Redacted, never silently dropped

An ungrounded claim is replaced with a visible marker and flagged with a reason. A defence whose failure mode is invisible is worse than no defence.

The simulated model is a deterministic stand-in that fabricates references on a fixed subset of findings, so the checks have something to catch without anyone paying for tokens. It is not evidence about how any real model behaves — use your own key for that.
